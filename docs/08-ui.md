layout, components, copy rules, and the visual system.

## 2. Design direction

Reference: dhealth.co.id for **structure and tone** (B2B health, trust-first,
editorial spacing, big type). Not for assets, copy, or layout clones.

The feeling: **calm clinical confidence.** White space, one deep teal accent,
warm neutrals, no gradients, no glassmorphism, no stock-photo doctors. Product
UI is shown as literal UI, not glossy mockups.

### 2.1 Tokens

| Token | Value | Use |
|---|---|---|
| `--ink` | `#0B1F2A` | headings, primary text |
| `--ink-2` | `#3E5663` | body text |
| `--muted` | `#6B7C88` | captions, meta |
| `--line` | `#E3EAEE` | borders, dividers |
| `--bg` | `#FFFFFF` | page |
| `--bg-alt` | `#F6F9FA` | alternating sections, app canvas |
| `--brand` | `#0E7C7B` | primary CTA, links, active nav |
| `--brand-ink` | `#0A5C5B` | hover, pressed |
| `--brand-weak` | `#E6F4F2` | badges, selected rows |
| `--accent` | `#C8E86B` | one highlight per page, max |
| `--ok` | `#1F7A4D` | connected, ready |
| `--warn` | `#8A5A00` | degraded |
| `--danger` | `#A4262C` | destructive, errors |
| `--focus` | `#0E7C7B` + 2px offset ring | keyboard focus |

Type: **Plus Jakarta Sans** (400/500/600/700) via `next/font`, fallback system.
Scale: 12 / 14 / 16 / 18 / 22 / 28 / 36 / 48 / 60 px. Headings tight
(`-0.02em`), body `1.6` line-height, max measure 68ch.

Spacing: 4px base → 4/8/12/16/24/32/48/64/96/128.
Radius: 6 (inputs), 10 (cards), 999 (pills).
Shadow: one level only, `0 1px 2px rgba(11,31,42,.06)` plus border.
Containers: 1200px marketing, 1320px app, 16px gutters at mobile.

Rules: no more than **one** accent-coloured element per viewport. Colour never
carries meaning alone — always pair with text or icon.

### 3.2 `/solusi`

Category anchors (`#berkas`, `#anggota`, `#integrasi`, `#audit`), each with: what
it does, who uses it, one screenshot, 3 bullets, link to demo. Sticky sub-nav on
desktop, select on mobile.

### 3.3 `/integrasi`

Three cards with **honest** status:

| Integration | Status shown |
|---|---|
| SATUSEHAT | `Mode uji` — pipeline built, production access pending |
| BPJS | `Direncanakan` |
| LIS/RIS | `Direncanakan` |

Explain the real constraint: production SATUSEHAT access requires a registered PT
and faskes onboarding. This is a differentiator, not an embarrassment.

### 3.4 `/demo`

Two-column: form left, what-happens-next right (3 steps, response expectation).
Fields: nama, email, nama faskes, jenis faskes (select), kota, telepon (optional),
pesan (optional). Honeypot hidden field + `elapsed_ms`. Success replaces the form
with a confirmation panel; never a toast that disappears.

### 3.5 `/tentang`, `/faq`, `/privasi`

- Tentang: story, what we believe, team placeholders clearly marked, address,
  contact.
- FAQ: 10 questions, including "Apakah ini produk resmi Kemenkes?" → **no**,
  with a link to the disclaimer.
- Privasi: what we collect (leads, session cookies), why, retention (12 months for
  leads), how to request deletion, contact. Plain language, no legal theatre.

### 3.6 404 / 500

Branded, one sentence, links home and to demo. 500 never shows a stack trace or a
request id in the body (it goes to logs).

## 4. Auth pages

Centered card, max 420px, one action per screen.

- `/masuk`: kode faskes, email, kata sandi, `Masuk`, link to reset. Uniform
  `Email atau kata sandi salah` — never reveals which.
- `/daftar`: only for invited users in v0.1.0; without an invite it explains that
  the faskes admin must invite them and links to `/demo`.
- `/lupa-sandi`: email → always the same 202-style message.
- `/ops/masuk`: separate, minimal, no marketing nav.

Validation: inline under the field, `aria-describedby`, focus moves to the first
error. Submit button shows a pending state and is disabled once.

## 5. Faskes app

Shell: 240px sidebar (collapsible under 1024px), top bar with tenant badge,
search (files only), user menu. Canvas `--bg-alt`, cards white.

### 5.1 `/app/dasbor`

Row 1: 4 stat cards (berkas, kuota terpakai, sinkronisasi terakhir, status
integrasi).
Row 2: quota bar with numeric label; activity list (last 8 audit events).
Row 3: "Yang perlu perhatian" — failed job, unverified credentials, near-quota.
Empty state: onboarding checklist (unggah berkas pertama, hubungkan integrasi).

### 5.2 `/app/berkas`

- Drop zone: "Tarik berkas ke sini atau pilih" + allowed types and max size, always
  visible.
- Upload row appears immediately with filename, size, progress, cancel.
- Table: nama, ukuran, status, pengunggah, waktu, aksi (unduh, hapus).
- Delete: inline two-step confirm.
- Errors mapped from storage: too large, wrong type, expired, unavailable.

### 5.3 `/app/anggota`

Table + role select. Admin sees member/admin; owner also sees owner. Last-owner
error inline and select reverts. Invite button disabled with tooltip "Segera
hadir" and a mailto fallback — do not fake an invite flow.

### 5.4 `/app/integrasi`

Sections: status summary, credentials form (secret write-only), test connection,
sync buttons, job history with polling while active, error detail as `<details>`.
Persistent `Mode uji` band; no green success theatre.

### 5.5 `/app/profil`, `/app/pengaturan`

Profile: display name, timezone, avatar (reuses files). Settings: language display,
timezone, sign out all sessions. No dead toggles.

## 6. Ops

Separate shell, denser type, no marketing chrome.

- `/ops/tenant`: table (slug, nama, status, anggota, dibuat), detail drawer,
  provision dialog with step timeline, suspend/resume with reason.
- `/ops/audit`: filters (tenant, action, date), virtualised table, export CSV.
- `/ops/kesehatan`: dependency status, build version, uptime, queue depth,
  last migration per tenant.

Tenant owners who hit `/ops` get 403 and no nav entry.

## 8. Motion

- Duration 120–200ms, easing `cubic-bezier(.2,.8,.2,1)`.
- Animate `opacity` and `transform` only; never `height` or `top`.
- One reveal per section on scroll, 12px rise, once. No parallax, no counters that
  animate numbers (they lie at a glance).
- `prefers-reduced-motion: reduce` disables all of it.
- Page transitions: none. Instant navigation beats choreography.

## 9. Accessibility

- WCAG 2.2 AA: body text ≥ 4.5:1, large text ≥ 3:1, focus ring never removed.
- Landmarks (`header/nav/main/footer`), one `h1` per page, skip link.
- Mobile drawer traps focus, closes on `Esc`, restores focus to the trigger.
- Tables use `<th scope>`; row actions have accessible names ("Hapus
  hasil-lab.pdf", not "Hapus").
- Forms: label + hint + error wired with `aria-describedby`; errors announced via
  `role="alert"`.
- Test with keyboard only and VoiceOver once per milestone.

## 10. Copy and legal

- Bahasa Indonesia only in v0.1.0. All strings in `lib/copy/id.ts`, typed; a test
  fails on hard-coded Indonesian in components.
- Tone: direct, specific, no superlatives. "Satu alur kerja untuk berkas dan
  integrasi" beats "solusi terbaik".
- Never claim: official Kemenkes affiliation, ISO certification, customer counts,
  or clinical outcomes. Those require evidence.
- Illustrative numbers (if used at all) carry a visible `Ilustrasi` label.
- Footer on every page: *"Sehat Bridge adalah proyek independen dan tidak
  berafiliasi dengan Kemenkes."*
- Privacy page states lead retention (12 months) and cookie usage in plain words.

## 12. Explicitly excluded

- No blog/CMS, case studies, careers, or resource library in v0.1.0.
- No patient-facing booking or chat.
- No clinical screens in the app (no patients, encounters, prescriptions).
- No dark mode.
- No fake testimonials, logos, or certification badges.
- No animation library beyond small CSS/`motion` usage.
